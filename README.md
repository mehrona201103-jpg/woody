# Woody v0.3

Голосовой AI-компаньон: FastAPI + SQLite + vanilla JS. Woody Core (личность, память, эмоции, права) отделён от AI-моделей (AI Router).

## Быстрый запуск
Windows: двойной клик по `start.bat`. Linux/macOS: `./start.sh`. Скрипт сам создаст окружение, поставит зависимости, создаст `.env` (впишите туда ключи ИИ) и откроет http://localhost:8000.

**Несколько ИИ сразу:** Woody Code запускает ВСЕ настроенные ключи параллельно (AI_PROVIDER_1..7, OPENAI_API_KEY, OPENAI_API_KEY_2, OPENROUTER, GROQ, DEEPSEEK), сравнивает ответы и собирает лучший.

## Локальный запуск
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите AI_PROVIDER_1_API_KEY
uvicorn backend.main:app --reload
# открыть http://localhost:8000
pytest
```

## Деплой на Render
1. Загрузите папку на GitHub (`.env` в репозиторий не попадает).
2. Render → **New → Blueprint** → выберите репозиторий (файл `render.yaml` подхватится).
3. В **Environment** задайте Variables (см. ниже) и нажмите Deploy.
4. Откройте URL сервиса; при первом входе браузер спросит `WOODY_ACCESS_TOKEN` (возьмите его в Environment).

### Variables
| Ключ | Обязательно | Значение |
|---|---|---|
| `AI_PROVIDER_1_BASE_URL` | да | напр. `https://api.openai.com/v1` (любой OpenAI-совместимый API) |
| `AI_PROVIDER_1_API_KEY` | да | ключ провайдера (секрет) |
| `AI_PROVIDER_1_MODEL` | да | напр. `gpt-4o-mini` |
| `AI_PROVIDER_1_NAME` / `_TASKS` | нет | `main` / `conversation` (также `vision,coding,translation`) |
| `AI_PROVIDER_2_*` … `5_*` | нет | резервные провайдеры, тот же формат |
| `WOODY_ACCESS_TOKEN` | **да** | пароль доступа к API (в render.yaml генерируется автоматически) |
| `PYTHON_VERSION` | да | `3.12.8` |
| `APP_ENV` | нет | `production` |
| `LOG_LEVEL` | нет | `INFO` |
| `PUBLIC_BASE_URL` | нет | Адрес для QR (`https://woody.onrender.com`). На Render берётся из `RENDER_EXTERNAL_URL` автоматически; на своём домене задайте вручную |
| `WOODY_DB_PATH`, `WOODY_SHARED_DIR` | нет | `/var/data/woody.db`, `/var/data/shared` — только с Persistent Disk |

## Деплой на Railway
1. Загрузите папку на GitHub (`.env` в репозиторий не попадает).
2. Railway → **New Project → Deploy from GitHub repo**. Конфигурация берётся из `railway.json` (старт, healthcheck `/api/health`).
3. **Settings → Networking → Generate Domain** (публичный адрес; от него строится QR).
4. **Variables** — добавьте:

| Ключ | Значение |
|---|---|
| `AI_PROVIDER_1_BASE_URL` | напр. `https://api.openai.com/v1` |
| `AI_PROVIDER_1_API_KEY` | ключ провайдера (секрет) |
| `AI_PROVIDER_1_MODEL` | напр. `gpt-4o-mini` |
| `WOODY_ACCESS_TOKEN` | придуманный длинный пароль (**обязательно**) |
| `APP_ENV` | `production` |
| `WOODY_DB_PATH` | `/data/woody.db` |
| `WOODY_SHARED_DIR` | `/data/shared` |
| `PUBLIC_BASE_URL` | необязательно; по умолчанию `https://$RAILWAY_PUBLIC_DOMAIN` |

5. **Постоянная память:** сервис → правый клик / `⌘K` → **Add Volume**, mount path `/data`. Без Volume база SQLite стирается при каждом деплое.
6. Откройте домен: браузер спросит `WOODY_ACCESS_TOKEN`. Держите ровно **1 реплику** (SQLite и ожидающие подтверждения живут в одном процессе).

## Чтобы база НЕ стиралась (важно)
SQLite-файл на Render Free / Railway без диска стирается при каждом деплое. Выберите один из способов (лучше сразу два):

1. **Postgres (рекомендую, бесплатно):** создайте базу на Neon / Supabase / Railway Postgres и добавьте переменную `DATABASE_URL` (строка подключения). База живёт отдельно от сервера — деплои и перезапуски её не трогают. Таблицы и миграции создаются сами.
2. **Volume / Disk:** Railway → Add Volume, mount path `/data`; Render (платный план) → Disk `/var/data`. Woody сам найдёт `/data`, `/var/data` или `RAILWAY_VOLUME_MOUNT_PATH` и положит туда базу — переменные `WOODY_DB_PATH` задавать не нужно.
3. **Страховка для мозга:** Settings → «Сохранить мозг в файл» скачивает `brain_seed.json`. Положите его в репозиторий как `data/brain_seed.json` — если база пуста, Woody при старте сам вернёт мозг из файла.

В Settings → «Мозг Woody» и в логах сервера Woody прямо пишет, постоянная ли сейчас база.

## Что нового в v0.3
- **Создатель.** На вопрос «кто тебя создал?» Woody отвечает: «Меня создал 17-летний мальчик Ибрагимов Мухаммад. Я постоянно учусь и развиваюсь вместе с вами.» OpenAI он называет только своим инструментом.
- **Свой мозг (самообучение).** Не знает ответа → спрашивает AI-ключ → запоминает вопрос и ответ в таблицу `learned_answers`. Знакомый вопрос → отвечает сам (экономит лимит). Когда лимит ключа закончился или сеть пропала → ищет похожий вопрос в мозге и отвечает из него. Простая арифметика (`1+1`) считается локально без ключа. Личные вопросы («как меня зовут», «моя…») и «живые» (погода, время) в общий мозг не попадают.
- **«Обучай самого себя».** Woody закрывает глазки, над головой после бровей появляется эффект обучения; сервер сам изучает темы через ключ и складывает знания в мозг, пока лимит не закончится (или не скажешь «хватит учиться»). Максимум за запуск — `SELF_LEARN_MAX` (по умолчанию 400 записей).
- **Голос как у человека.** Серверный голос (`/api/tts`, OpenAI-совместимый `audio/speech`, тот же ключ; 8 голосов на выбор), речь по предложениям, рот двигается по реальной громкости. Нет серверного голоса → лучший русский голос браузера с живыми паузами. Настройки: Settings → Voice.
- **Голос = «в себе».** В голосовом разговоре Woody только говорит — в чат ничего не пишется (и не сохраняется в историю чата). В текстовом — пишет.
- **Живые глаза и камера.** Камера включается при запуске (один раз спросит разрешение), глаза следят за рукой и за любым движением в кадре, моргают (иногда дважды), «дышат», зрачки расширяются; резкое движение → удивление; помахал рукой → здоровается. «Что ты видишь?» — кадр отправляется в AI только по этой просьбе и нигде не сохраняется.
- **Приглашение жестом 👍 / 👆.** Показал палец → экран «как AirDrop» (радар, найденное устройство, пузырь Woody летит к нему) → системное меню «Поделиться» с одноразовой ссылкой-приглашением; QR — запасной путь.
- **Доступ к устройству по разрешениям.** Новые разрешения: геолокация, буфер обмена, состояние устройства, приглашения. Если разрешено — Woody делает сразу (время, батарея, «где я», вибрация, буфер, напоминания-уведомления, снимок, включить/выключить камеру). Кнопка «Разрешить Woody всё» в настройках (кроме удаления файлов — оно всегда с подтверждением).
- **Интерфейс.** Поле имени больше не лежит на рту: знакомство — отдельная карточка под лицом; новые пузыри чата, круглая кнопка отправки, камера-превью овалом.

### Новые переменные
| Ключ | Значение |
|---|---|
| `DATABASE_URL` | Postgres-строка подключения — база не стирается |
| `TTS_MODEL` / `TTS_BASE_URL` / `TTS_API_KEY` | необязательно; по умолчанию `gpt-4o-mini-tts` и ключ/адрес `AI_PROVIDER_1` |
| `SELF_LEARN_MAX` | максимум выученных записей за один запуск самообучения (400) |

### Честно о границах (браузерное приложение)
- Сайт **не может** «проникнуть» в систему: нет доступа к файлам, SMS, настройкам, чужому Bluetooth и работы после закрытия вкладки. Woody использует всё, что браузер разрешает (камера, микрофон, геолокация, уведомления, буфер, вибрация, «Поделиться»), и только с разрешения. Для настоящего фонового режима и Bluetooth нужно нативное приложение (Capacitor/Android) — это следующий этап.
- Приглашение уходит через системное меню «Поделиться» (AirDrop / Nearby Share / Bluetooth) — прямую передачу по Bluetooth из браузера отправить нельзя. Работает на HTTPS.
- Серверный человеческий голос и самообучение требуют рабочего AI-ключа с оплаченным лимитом.

## Что нового в v0.2
- Единый API-клиент (`js/api.js`), проверка `GET /api/health` → `{"status":"ok","service":"woody"}`, баннер «Не удалось подключиться к Woody» + «Повторить»; реальные ошибки — в console.

- Токены: 192 бита CSPRNG, TTL 5 мин, одноразовые, в БД только sha256.
- Изоляция: память, разрешения, настройки, история, эмоции — по `user_id`; Woody Identity общая. Сессия пользователя — секрет в браузере (в БД хэш).
- Миграция существующей БД v0.1 автоматическая; **старые глобальные разрешения сбрасываются** (теперь они персональные).

## Известные ограничения
- Free-план Render: SQLite стирается при перезапуске — используйте `DATABASE_URL` (Postgres), см. раздел выше.
- Голос (STT/TTS) работает через браузер; нужен HTTPS (Render даёт) и Chrome/Edge/Safari.
- Отправка сообщений/файлов не подключена к реальным каналам — Woody честно сообщает об этом.
- Пороги классификации жестов — эвристика; проверить на реальной руке и при необходимости подстроить в `gestures.js`.
- MediaPipe и qrcode.js грузятся с CDN (jsdelivr/cdnjs): нужен интернет на телефоне.
- Фоновый режим: только интерфейс-заглушка, Background Companion — TODO.
- Ожидающие подтверждения хранятся в памяти процесса (один worker).

## v0.4 — приложение в стиле ChatGPT, регистрация, Google, OpenRouter

**Что нового**
- Интерфейс как у ChatGPT: чат + отдельный голосовой режим, боковое меню, настройки-лист. Работает как приложение (PWA: «Добавить на главный экран»).
- Плавность: убраны тяжёлые эффекты (`filter`, `backdrop-filter`), анимации только на `transform/opacity`, лицо перерисовывается только при изменениях, жесты камеры — ~10 кадров/с.
- Живой голос без голоса браузера: OpenAI TTS (если есть ключ) → бесплатный нейронный голос `edge-tts` (запасной). Эмоции: смех, грусть, слёзы, удивление.
- Голосовой режим: микрофон слушает постоянно, камера включена, касание лица — перебить Woody. «Давай в чат» / «давай на голосовой режим» переключают режимы, разговор общий.
- Регистрация и вход: почта + пароль + имя, кнопка «Продолжить с Google», анимация после регистрации.

**Variables (Railway / Maze Host → Variables)**

OpenRouter как второй ИИ (самый простой способ):

```

```

Authorized JavaScript origins: адрес вашего сайта (https://…up.railway.app). Redirect URI не нужен.

Рекомендуется для постоянных аккаунтов: `DATABASE_URL` (Postgres). `WOODY_ACCESS_TOKEN` теперь можно не задавать — вход защищён регистрацией.

## Android APK / AAB через PWABuilder

Проект подготовлен для упаковки сайта Woody AI в Android Trusted Web Activity (TWA) через PWABuilder:

- PWA manifest: `frontend/manifest.webmanifest` — добавлены стабильный `id`, категории приложения, `display_override` и `prefer_related_applications: false`.
- Иконки `frontend/assets/icon-192.png` и `icon-512.png` обновлены логотипом Woody AI, который предоставил владелец проекта; изображение размещено с безопасными отступами для maskable-иконок.
- `frontend/index.html` подключает обновлённый manifest и новую иконку.
- Service worker использует новый ключ кэша `woody-shell-v071`, чтобы обновлённые ресурсы не застревали в старом кэше.

### Сборка

1. Разверните обновлённый проект на HTTPS-домене и убедитесь, что открываются `/manifest.webmanifest`, `/assets/icon-192.png`, `/assets/icon-512.png` и `/sw.js`.
2. Откройте `https://www.pwabuilder.com/`, укажите адрес сайта Woody AI и нажмите **Package For Stores**.
3. Выберите Android / Google Play и задайте уникальный Android package ID (например, `com.woodyai.app`, только если он ещё не занят и вы хотите закрепить именно его).
4. Создайте signing key и сохраните keystore и пароли в надёжном месте. Не публикуйте их в GitHub и не отправляйте третьим лицам.
5. Скачайте пакет PWABuilder: в нём должны быть APK для тестирования и AAB для Google Play.
6. После получения SHA-256 сертификата подписи добавьте Digital Asset Links в `/.well-known/assetlinks.json` на домене сайта. Для публикации через Google Play также добавьте SHA-256 сертификата **Play App Signing** из Play Console. Не используйте примерные/фиктивные отпечатки.

### Что ещё нужно сделать в PWABuilder

- Добавить реальные скриншоты экранов Woody AI в разделе Screenshots. В архиве нет достоверных скриншотов приложения, поэтому рекламное изображение не подставлялось как скриншот.
- `related_applications` пока не добавлен: у проекта ещё нет опубликованного Android-приложения с подтверждённым Play Store ID. После публикации можно указать его и решить, предлагать ли пользователям нативную версию.

Важно: TWA — это Android-оболочка сайта. Основная логика и API Woody AI продолжают работать на сервере Railway; это не переносит Python backend внутрь APK. Для публикации потребуется аккаунт Google Play Console и соблюдение актуальных требований Google Play.

### Push-уведомления групп

Чтобы сообщения приходили даже когда PWA свёрнуто или закрыто, сгенерируй пару VAPID-ключей (`npx web-push generate-vapid-keys`) и задай `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_CLAIMS_EMAIL` в переменных сервера. Пользователь должен разрешить уведомления при первом открытии группы. Без VAPID-ключей работают только уведомления внутри открытого приложения.
